# MindAgent 业务提案

> 状态：Accepted
>
> 本文定义 MindAgent 为什么存在、首个版本交付什么以及明确不做什么。强制行为与接口见 [spec.md](spec.md)，实现方案见 [design.md](design.md)。技术设计不得扩大本文范围。

## 1. 产品定位

MindAgent 是**支持群聊交互场景的多用户智能体工作台**，面向单个企业或团队的线上协同场景，以单机自托管方式运行。

MindAgent 解决两类问题：

- 单人分别部署智能体会重复消耗模型、运行环境和维护资源，团队资料与成果也难以复用；
- 传统群聊机器人容易出现多用户上下文串扰、耗时任务阻塞会话以及公共与私人数据边界不清等问题。

系统以“**团队公告资料共享 + 用户独立 Workspace 隔离**”为核心：团队共用 Agent 服务、模型、基础 Skills 和管理员维护的公告资料；每名用户拥有独立上下文、记忆、文件、任务和运行状态。

## 2. 目标用户与角色

### 2.1 普通用户

普通用户通过 QQ 私聊或群聊使用 Agent，不登录 Web 工作台。用户在第一次发送私聊消息或第一次在群内 `@Agent` 时自动获得 MindAgent 身份与独立 Workspace。

普通用户可以：

- 在私聊中直接向 Agent 提问或交付任务；
- 在群聊中通过 `@Agent` 显式触发交互；
- 使用自己的上下文、记忆、文件、Skills 和任务产物；
- 让 Agent 按需读取当前群历史；
- 让 Agent 查询和读取团队公告资料；
- 将耗时任务交给 Sub-agent，并查询、取消或接收任务结果。

### 2.2 管理员

管理员通过本地 Web 工作台管理系统，是首版唯一可以登录 Web 的角色。管理员拥有完整管理权限，包括查看、修改和删除所有用户 Workspace 中的私有数据。

管理员可以：

- 管理用户、Workspace、会话、记忆、文件和任务；
- 上传、覆盖、移动和删除团队公告资料；
- 配置 QQ 渠道、模型、Skills、工具、并发限制和系统参数；
- 查看运行状态、错误信息和基础调用链；
- 执行备份、恢复和版本迁移；
- 使用管理员测试会话验证模型与工具。

首版不向普通用户提供 Web 登录、邀请、自助认领或账号绑定流程。

## 3. 首版业务范围

### 3.1 多用户与 Workspace

- 一个 MindAgent 实例服务一个团队；
- 用户在首次有效触发时自动创建；
- 每名用户拥有且仅拥有一个独立 Workspace；
- 用户的私聊、群聊上下文、记忆、文件、任务和 Agent 状态相互隔离；
- 管理员可以禁用用户或明确删除其 Workspace；
- 团队共用运行服务、模型配置、基础 Skills 和公告资料。

### 3.2 QQ 交互

- 首版唯一正式支持的 IM 渠道是 QQ；
- QQ 接入使用 NapCat 与 OneBot v11；
- 支持私聊、群聊、`@Agent`、引用、提及、表情、图片、语音、视频、文件、历史查询和常用 QQ 动作；
- 私聊消息直接触发 Agent；
- 群聊只有 `@Agent` 的消息触发 Agent，普通消息不触发回复；
- 群聊中不同用户可以并发调用，同一用户在同一群内保持顺序；
- 群历史由 QQ 渠道按需提供，不作为长期上下文全量注入。

### 3.3 主 Agent 与 Sub-agent

- 主 Agent 负责实时会话、短时工具调用、上下文管理和任务分派；
- Sub-agent 只处理主 Agent 为用户明确创建的耗时任务；
- Sub-agent 在独立 run、checkpoint 和任务上下文中执行，不阻塞主 Agent；
- Sub-agent 只提交候选结果与产物，不直接向用户发送结果；
- 主 Agent 根据创建任务时保存的原始要求，对候选结果进行独立验收；
- 验收通过后，由主 Agent 整理最终回复并返回发起用户与原始会话；
- 验收不通过时允许一次带明确意见的自动返工，再次不通过则终止任务并向用户说明；
- 任务支持排队、执行、验收、状态查询、取消、失败和最终结果回投；
- Sub-agent 不拥有独立长期人格，不自行寻找、规划或创建任务。

### 3.4 团队公告资料

团队公告资料是管理员维护、供 Agent 阅读的共享文件目录，不是协作网盘、知识图谱或自动记忆系统。

- 只有管理员能通过 Web 创建、修改、移动或删除资料；
- 普通用户不能直接查看或修改 Web 资料目录；
- Agent 只能列举目录、按文件名过滤和读取指定文件；
- 用户私人数据不会自动进入公告目录；
- 首版不建立 embedding、向量索引或自动知识提炼。

### 3.5 Web 工作台

首版提供完整的管理员 Web 工作台，包含：

- 登录与系统状态；
- 用户与 Workspace 管理；
- 对话、记忆、文件和任务管理；
- 团队公告资料管理；
- QQ 渠道、模型、Skills、工具和系统配置；
- 备份、恢复与升级迁移；
- 管理员测试聊天。

### 3.6 渠道扩展边界

核心领域模型不依赖 QQ/OneBot 类型，渠道通过统一消息与能力契约接入。首版只实现 QQ；企业微信、飞书等仅作为未来扩展方向，不属于首版交付与验收范围。

## 4. 数据边界

MindAgent 将数据分为三层：

| 层级 | 内容 | 使用边界 |
| --- | --- | --- |
| 用户私有 | 上下文、记忆、文件、Skills、任务与产物 | 当前用户及其 Agent；管理员可通过 Web 完整管理 |
| 群内共享 | 群消息、群文件、群成员信息 | 仅由渠道按需提供给当前群中的当前运行 |
| 团队公告 | 管理员维护的共享文件 | 所有用户可通过 Agent 只读查询 |

私人内容不会自动发布为团队资料，群历史不会自动转化为用户记忆或团队知识。

## 5. 成功标准

首版成功必须同时满足：

- 多名用户可以共用一个实例，而不会发生上下文、记忆、文件或任务串用；
- 群聊普通消息不触发 Agent，`@Agent` 后能获得稳定回复；
- Agent 可以按需查询当前群历史，但不会长期保存普通群消息；
- 主 Agent 在 Sub-agent 执行期间保持可交互；
- Sub-agent 候选结果经过主 Agent 验收，只有合格结果才会作为任务成果返回用户；
- 异步任务可查询、取消、返工，并可靠地把最终状态返回原始会话；
- 团队公告资料只有管理员可写，普通用户只能经 Agent 读取；
- 服务重启后用户、Workspace、会话与任务状态不会无故丢失；
- 管理员可以在 Web 中完成日常管理、诊断、备份和恢复；
- QQ 之外的渠道可以在不改变核心 Workspace 和任务语义的前提下后续接入。

## 6. 明确非目标

以下内容不属于首版，AI 编码时不得自行添加：

- 企业微信、飞书或其他非 QQ 渠道的具体实现；
- 普通用户 Web 登录、邀请、自助认领和账号绑定；
- 跨用户统一全局记忆、统一人格或统一心智；
- 私有数据、群历史或任务结果自动沉淀为团队公告资料；
- Agent 主动发言、空闲巡检、心跳、自主触发回复或自主创建任务；
- 复杂话题自动聚类、话题空间、知识图谱和跨群认知融合；
- 公告资料 embedding、向量检索和独立 RAG 平台；
- 独立 Worker、领域微服务、外部 PostgreSQL、水平扩容和多机运行；
- 面向多个组织的 SaaS 多租户；
- 重型企业审计、精细资源计费、复杂 RBAC 和多级组织隔离；
- 多 Provider 管理、本地模型下载和内置推理；
- 通用低代码 Agent 编排平台；
- 对 QwenPaw 功能、代码或目录结构的完整复制。

基础日志、管理员操作记录、用户隔离、任务并发限制和必要权限校验仍属于系统稳定运行所需能力，不视为重型企业治理。
