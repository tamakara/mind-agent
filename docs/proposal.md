# WorkHub 业务提案

> 状态：Accepted
>
> 本文定义首版产品模型、用户可见能力和范围。强制行为见 [spec.md](spec.md)，实现方案见 [design.md](design.md)。

## 1. 产品定位

WorkHub 是面向单个企业部署的对话式企业服务入口。员工通过飞书机器人私聊，用自然语言完成制度查询和简单 OA 操作，不需要分别理解请假、报销、IT 工单等内部系统的入口和表单。

首版只实现“查询年假余额、提交年假申请、查询业务审批进度”这一条最小闭环。系统以目录化知识库解释公司制度，以 MCP 连接模拟 OA，并在提交真实业务请求前取得员工本人确认。

## 2. 身份与隔离

- 一个实例只绑定一个企业和一个飞书自建应用；
- 管理员在 WorkHub 内维护员工号、姓名、部门、主管、时区和在职状态；
- 飞书 `open_id` 通过 `ChannelIdentity` 映射到内部员工；
- 未绑定身份首次私聊时只登记待绑定身份并返回提示，不创建 Agent run；
- 每名已启用员工拥有一个稳定 Session，同一员工的 run 串行、不同员工并发；
- 历史、待确认动作、工具主体和审计始终绑定内部员工 ID，不依赖模型提供的员工号；
- 首版不从飞书通讯录同步员工，也不允许 Agent 修改员工资料。

## 3. 飞书入口

首版使用飞书官方 SDK 长连接接收事件，不要求部署公网回调地址。只支持：

- 机器人一对一私聊文本输入；
- 机器人文本回复；
- 用户确认或取消操作的交互卡片；
- 卡片动作结果更新。

群聊、图片、语音、视频、文件、引用消息、外部聊天历史查询和第二渠道均不在首版范围。WorkHub 自己保存的 Session 历史是唯一对话上下文来源。

## 4. 用户确认与业务审批

用户确认和业务审批是两个不同阶段：

1. Agent 整理出请假日期、类型和天数；
2. `submit_leave_request` 的 MCP 策略为 `confirm`，WorkHub 创建持久化待确认动作；
3. 飞书卡片向申请人展示不可变摘要；
4. 申请人点击“确认提交”后，WorkHub 调用模拟 OA；
5. 模拟 OA 创建申请并进入 `pending_approval`；
6. 主管或人事审批发生在 OA 内，WorkHub 不实现该审批；
7. 员工可通过 `query_leave_request_status` 查询进度。

待确认动作不依赖一个持续等待的模型调用。创建动作后当前 Agent run 正常结束；卡片回调作为新的确认回合执行，因此用户等待期间仍可继续聊天，服务也不需要长期占用 Session 锁或 MCP 连接。

## 5. Agent 能力

### Runtime

主 Agent 同步处理每次飞书私聊。运行时注入代码维护的办公助手规则、可信 `ActorContext`、当前 Scroll 窗口、知识工具和已启用 MCP 工具。模型不能指定或更改调用主体。

### Context / Scroll

系统逐字保存用户消息、Agent 回复、工具调用、工具结果和确认事件。每个完整回合保存一个 headline；达到 token 预算后从最旧完整回合开始驱逐，并保留 headline 导航。Agent 可在当前员工 Session 内展开或搜索旧回合原文。

首次申请回合以“等待用户确认”结束。点击卡片后创建独立确认回合，记录确认决定、MCP 调用结果、业务单号和最终回复。

### Knowledge / RAG

管理员在 Web 中以目录树管理 UTF-8 Markdown/TXT 文档。原始目录和文件是知识正文真相来源；保存内容后自动计算哈希、切片和 Embedding。新索引完整构建成功后才替换旧索引，失败不影响现有查询。

首版所有文档对全员可见。检索结果必须包含文档、目录、版本、标题路径和原文行号，Agent 可以回读原文后回答。

### MCP

首版只支持 Streamable HTTP。工具暴露与执行策略分开管理，策略为：

- `allow`：直接执行只读或低风险操作；
- `confirm`：先持久化动作并由当前员工确认；
- `deny`：不得连接执行端。

新发现工具默认 `deny`。模拟 OA 提供：

- `query_leave_balance`：`allow`；
- `submit_leave_request`：`confirm`；
- `query_leave_request_status`：`allow`。

### 员工资料

员工资料是结构化、管理员维护、Agent 只读的数据。首版不提供自由文本 Profile、长期 Memory 或自动记忆整理。个性化上下文仅来自可信员工字段和当前 Session 历史。

## 6. 管理员 Web

首版管理端提供：

- 管理员登录；
- 概览与健康状态；
- 员工资料、启停和飞书身份绑定；
- 知识目录与文档编辑、索引状态和失败重试；
- OpenAI-compatible Chat/Embedding 配置与连通性测试；
- MCP 客户端、工具发现、白名单和策略；
- 飞书连接与待绑定身份状态；
- 操作、确认和工具调用审计。

普通员工不登录 Web，Web 不提供测试聊天或业务审批入口。

## 7. 本地演示剧本

**员工：** “我想休下周一和周二的年假，帮我走一下流程。”

**Agent：** 检索《员工请假制度.md》，调用 `query_leave_balance`，确认余额为 5 天，并生成确认卡片。

**确认卡片：** 显示日期、假期类型、天数和当前余额；提供“确认提交”和“取消”按钮。

**员工：** 点击“确认提交”。

**Agent：** “年假申请已提交，申请单号 LV-20260721-001，当前状态：等待业务审批。”

**员工：** “刚才的申请审批了吗？”

**Agent：** 调用 `query_leave_request_status` 并返回 `pending_approval`、`approved` 或 `rejected`。

模拟 OA 提供受管理令牌保护的 REST 接口供演示人员改变业务审批状态；该接口不注册为 MCP 工具。

## 8. 首版范围与非目标

首版实现飞书文本私聊、员工绑定、单 Session、Scroll、目录化 RAG、Streamable HTTP MCP、持久化确认、模拟 OA、审计和最小管理端。

首版不实现 QQ/OneBot/NapCat、群聊、附件、多渠道、多企业租户、飞书通讯录同步、用户文件目录、Workspace、PROFILE/MEMORY、Persona 管理、Skills、Sub-agent、通用后台 Tasks、报销、撤销请假、主管/财务审批、知识分级权限、MCP OAuth、备份恢复或多服务 Worker。知识索引队列是内部维护机制，不属于 Agent 长任务能力。
