# MindAgent 业务提案

> 状态：Accepted
>
> 本文只定义首版业务目标、范围与非目标。强制行为见 [spec.md](spec.md)，实现方案见 [design.md](design.md)。

## 1. 产品定位

MindAgent 是面向团队群聊场景的多用户智能体工作台。一个实例服务一个团队，多名用户共用 Agent 服务，每名用户拥有独立 Workspace，避免上下文、文件和任务相互串扰。

首版以 QQ 为唯一入口，重点完成群聊并发、长任务异步执行和公共文档读取，不追求完整平台能力。

## 2. 首版范围

### QQ 交互

- 使用 NapCat / OneBot v11 接入 QQ 私聊和群聊；
- 私聊消息直接触发 Agent，群聊只有 `@Agent` 时触发；
- 群聊中每名用户拥有独立上下文，不同用户可以并发调用；
- Agent 可以按需查询当前群历史，不全量注入群消息；
- 常用消息支持文本、提及、引用、图片、语音、视频和文件。

### 用户与 Workspace

- 用户首次发送私聊或首次在群内 `@Agent` 时自动创建；
- 每名用户拥有一个独立 Workspace；
- Workspace 保存逐字会话历史、用户文件、Agent 产物和异步任务数据；
- 管理员可以查看 Workspace 文件并启用或禁用用户。

### Agent 与任务

- 主 Agent 负责实时会话和短任务；
- Sub-agent 在后台执行耗时任务，不阻塞主 Agent；
- Sub-agent 只提交候选结果，不直接回复用户；
- 主 Agent 根据原始要求验收候选结果，通过后生成最终回复；
- 首次验收不通过时自动返工一次，再次不通过则结束任务并说明原因。

### 简化 Scroll

- 触发对话、Agent 回复和工具结果逐字保存；
- 模型上下文只保留当前会话最近的完整轮次；
- 旧轮次被驱逐后仍可按序号展开或搜索；
- 不生成摘要，不提炼长期记忆，不跨会话召回。

### 全局人设

全团队共用一套 Agent 人设，由管理员在 Web 编辑：

- `AGENTS.md`：工作规则与操作约束；
- `SOUL.md`：性格、语气和行为边界；
- `PROFILE.md`：MindAgent 的名称、定位和能力。

### 知识库

知识库在首版只是管理员维护、Agent 只读的公共文件目录：

- 管理员通过 Web 管理目录和文件；
- Agent 可以列举和读取文件；
- 普通用户通过 Agent 使用知识库，不直接登录 Web。

### Web 工作台

首版只提供管理员 Web 工作台，包含：

- 登录与概览；
- 用户列表与启用/禁用；
- Workspace 文件管理；
- 全局人设文件编辑；
- 知识库文件管理；
- 异步任务查看与取消；
- OpenAI 兼容模型配置；
- QQ 连接状态；
- 管理员测试聊天。

QQ 页面只读展示连接状态、登录账号、连接时间和最近错误，不提供 QQ 参数配置。

## 3. 明确非目标

以下能力不属于首版，开发时不得自行添加：

- Skills 加载、安装、管理及相关目录和 API；
- `MEMORY.md`、记忆提炼、用户画像和语义记忆；
- 企业微信、飞书等其他渠道，以及动态渠道插件框架；
- 知识库 RAG、embedding、向量检索和自动知识加工；
- Web 备份、恢复和升级迁移；
- 普通用户 Web 登录；
- Agent 主动发言、心跳、空闲巡检和自主创建任务；
- 跨用户统一心智、跨群认知融合；
- 外部 Worker、微服务、外部数据库和多机部署；
- 重型审计、复杂 RBAC 和资源计费。

统一消息模型只用于隔离 OneBot 与 Agent，不代表首版需要实现多渠道能力。
